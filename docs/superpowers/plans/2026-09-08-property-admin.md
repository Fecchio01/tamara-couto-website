# Property Administration Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a secure Supabase-backed administration panel that lets one authorized Tamara account manage property data, prices, locations, features, status, and photos while preserving the existing public site through a safe fallback migration.

**Architecture:** Keep the current static public site and add a browser-based `admin.html` protected by Supabase Auth. Store properties in PostgreSQL and images in Supabase Storage with RLS; expose only published properties to anonymous visitors and allow mutations only for rows associated with the single admin account. Introduce a repository adapter that prefers Supabase and falls back to the current `IMOVEIS_DATA` when configuration or network access is unavailable.

**Tech Stack:** Vanilla HTML/CSS/JavaScript, Supabase Auth, PostgreSQL, Supabase Storage, a pinned `@supabase/supabase-js` CDN version, Node built-in test runner, Supabase CLI migrations.

**Spec:** `docs/superpowers/specs/2026-09-08-property-admin-design.md`

## Global Constraints

- The site public must continue functioning with the current static data when Supabase is unconfigured or unavailable.
- No `service_role` key or other backend secret may appear in browser code, HTML, committed files, logs, or image URLs.
- RLS will be enabled on every exposed table.
- Anonymous users may read only `properties` rows with `status = 'published'`.
- Only the administrator identified in `admin_users` may create, update, publish, archive, or delete properties and storage objects.
- Authorization will not use user-editable `user_metadata`.
- Existing property cards, category filters, image navigation, modal, sharing, and map behavior must remain compatible with the legacy property shape.
- Each task ends with tests and its own commit; commits must be pushed to both `agent/sync-property-listings` and `main` after verification.

- Create `supabase-config.js`: local/runtime configuration, ignored from Git when it contains project values.
- Create `supabase-client.js`: browser-only client factory using the pinned public key.
- Create `property-repository.js`: public and admin data access methods.
- Create `property-source.js`: public loader that returns Supabase data or `IMOVEIS_DATA` fallback.
- Create `admin.html`, `admin.css`, and `admin.js`: login, protected dashboard, property form, list, status actions, and image management.
- Create `scripts/import-static-properties.mjs`: local-only importer for the existing `IMOVEIS_DATA` and `assets/imoveis` files.
- Modify `index.html`: load the configuration, Supabase client, and public source adapter before the current property UI.
- Modify `imoveis-ui.js`: await the source adapter without changing existing card/modal rendering contracts.
- Modify `.gitignore`: ignore local Supabase config and importer environment files while keeping the example config.

  normalizePropertyRow,

  const property = normalizePropertyRow(
    { id: 'p-1', legacy_id: '665313', title: 'Casa', type: 'Casa', price_cents: 25000000, status: 'published', features: ['Quartos: 3'] },
    [
      { storage_path: 'properties/p-1/02.jpg', sort_order: 2 },
      { storage_path: 'properties/p-1/01.jpg', sort_order: 1 },
    ],
  );
  assert.equal(property.price, 'R$ 250.000,00');
  assert.deepEqual(property.images, ['properties/p-1/01.jpg', 'properties/p-1/02.jpg']);
});

test('maps normalized data back to the public legacy shape', () => {
  const legacy = toLegacyProperty({ id: 'p-1', legacy_id: '665313', title: 'Casa', type: 'Casa', location: 'Campo Grande - MS', neighborhood: 'Centro', price_cents: 25000000, features: [], description: '', images: [], status: 'published' });
  assert.equal(legacy.id, '665313');
  assert.equal(legacy.price, 'R$ 250.000,00');
});

test('rejects an unpublished property without a title or category', () => {
  const result = validatePropertyInput({ title: '', type: '', status: 'draft' });
  assert.equal(result.valid, false);
  assert.deepEqual(result.errors, ['title', 'type']);
});

test('parses Brazilian price input into integer centavos', () => {
  assert.equal(parsePriceToCents('R$ 1.250.000,50'), 125000050);
});
